# Tay

Tay is a GPU-native, keyboard-first desktop app for working with AI coding agents. It combines
Claude Desktop-style chat (rendered markdown and diagrams) with real code navigation, review
and editing through an embedded Neovim. It is named after the River Tay.

**This is a learning project.** The main goal is to learn Rust and lower-level skills (async,
GPU rendering, text layout, IPC). Build time doesn't matter. When helping:
- Explain the why behind Rust and graphics concepts, not just the code.
- Keep steps small and runnable. Each milestone should end with something that works.
- Prefer simple, readable code over clever abstractions until a pattern has been needed twice.

(Edit this section if you want a different working style.)

## Architecture

Client/server, inspired by Superlogical's Rex:

- **`tayd` (daemon)** owns all state: agent sessions, a headless Neovim per open file, the
  repo (git status, diffs, file watching), conversation history, review comments, each chat's
  pane layout. Its file watcher keeps open Neovim buffers in sync with what the agent writes.
- **`tay` (client)** renders and forwards input. The GUI is winit + wgpu. A CLI exists from day
  one, and a TUI or mobile client could come later on the same protocol.
- **Start on demand:** the first `tay` command or the GUI starts `tayd`. It listens on a Unix
  socket at `$XDG_RUNTIME_DIR/tay/default` and exits shortly after nothing is attached, unless
  it was started explicitly.
- **Attach:** on connect the daemon sends a snapshot of current state, then a stream of events.
- **Protocol:** JSON for the API, so it's debuggable and callable from a shell or an agent.
  Every method is a Rust type with a JSON Schema generated by `schemars`. Use compact binary
  only for heavy streams such as Neovim screen updates.
- **Self-describing API:** `tay api list`, `tay api describe <method>`, `tay api call <method>
  '{...}'`. Agents can drive the app through it (for example `review.open`, `tab.open`).
- **MCP server:** `tay mcp` exposes the same API methods as MCP tools, so Claude Code, Codex and
  other agents can drive Tay without learning the CLI. It reuses the protocol types and schemas.
- **Remote (later):** listen on a tailnet address and trust Tailscale identity rather than
  building auth.

### Planned crates

```
tay/
  Cargo.toml          # workspace
  crates/protocol     # request, response and event types + JSON Schema
  crates/tayd         # daemon: tokio, UnixListener, length-delimited JSON framing
  crates/tay-cli      # `tay api list | describe | call`
  crates/client       # winit + wgpu GUI (later milestone)
```

### Key libraries

- Async and IPC: `tokio`, `tokio-util` (codecs), `serde`, `serde_json`, `schemars`
- Neovim: `nvim-rs`, running `nvim --embed` / `--listen`, using the linegrid UI protocol
- Agents: Zed's Agent Client Protocol (ACP) to wrap Claude Code, Codex, OpenCode and others.
  Tay doesn't build its own agent and must stay model-agnostic.
- GUI: `winit`, `wgpu`, `cosmic-text` (and glyphon for the glyph atlas)
- Markdown: `pulldown-cmark` or `comrak` (GitHub tables), `syntect` or tree-sitter for code
- Diagrams: the daemon renders Mermaid with `mmdc` to SVG, rasterises with `resvg` and caches by
  hash. Show the Mermaid source as a fallback. Pure-Rust layout (for example `layout-rs`) is a
  possible later learning project.

## UI model

- **Sidebar:** environments (a repo plus where it runs: this machine, a remote box over
  Tailscale, or a git worktree), each listing its chats with a status dot: working, needs you,
  done, idle.
- **Workspace per chat:** split panes, and every pane holds tabs: Chat, Diff, Code (browse),
  Neovim (edit), Terminal. One pane with tabs (Claude Code desktop feel) and split panes (Rex
  feel) are the same model. The daemon stores each chat's layout.
- **Default layout:** Chat on the left; Diff, Code, Neovim and Terminal tabbed on the right.
- **Worktree per chat:** each chat can run in its own git worktree on its own branch, so parallel
  chats don't collide and every chat's Diff is a clean branch to review.
- **Permission modes per chat:** Ask for everything, Auto-accept edits, or Full access. Built on
  ACP's permission requests, with the current mode shown in the chat's status line.
- **Review flow:** comment on diff lines GitHub-style, send one now or batch them into a review
  sent from the chat composer. The agent's changes come back into Diff.
- **Editing alongside the agent:** no file locks. You and the agent can both work on any file.
  - When the agent writes a file you have open with no unsaved changes, `tayd` reloads it in
    Neovim straight away (driven by the file watcher, not by waiting for `autoread`).
  - The lines the agent just changed are briefly highlighted, with a "changed by agent" note in
    the status line.
  - If you have unsaved changes when the agent writes the file, show a diff of the two versions
    with Keep mine / Take agent's / Merge, instead of Neovim's plain "file changed" warning.
  - Agents such as Claude Code already refuse to edit a file that changed since they read it, so
    your saved edits aren't silently overwritten. Worktrees per chat keep separate agents apart.
- **Keyboard:** modal and Vim-like throughout. Status lines show the mode (REVIEW, BROWSE,
  INSERT, NORMAL). `gt` for the next tab, `Ctrl-w v` to split, `Ctrl-w h/l` to move focus.

## Look

- Catppuccin Mocha palette. Accent Mauve `#CBA6F7`. Crust `#11111B` window, Mantle `#181825`
  panes and strips, Base `#1E1E2E` content. The app icon is peach on dark.
- Rex-like layout: rounded panes with small gaps, monospace UI chrome, Neovim-style status lines.
- Soft glass: subtle blur and a faint top highlight on panes, over a gentle mauve, blue and pink
  glow.
- Tabs like Dia: the selected tab is the same colour as the content and joins it, with
  outward-curved bottom corners. Inactive tabs are plain text.
- Chat prose uses a proportional font (IBM Plex Sans in the prototype). Code and chrome use
  JetBrains Mono.

`docs/prototype.html` is a clickable HTML prototype of the UI and workflow. Open it in a browser
as the visual reference. It is a sketch, not code to port. Its "Agent paused on this file" and
"Hand back to agent" banner is out of date: Tay no longer locks files.

## Related apps

Herdr, Orca and T3 Code cover similar ground. What makes Tay different: your real Neovim as the
editor, kept live in sync with the agent's edits; modal keyboard control; code review at the
centre; GPU-native rendering with diagrams in chat; and an API whose schemas come from the Rust
types. T3 Code's server and pairing design is
worth reading before building tayd's attach and remote support.

`docs/COMPETITORS.md` lists what users dislike about those apps and how Tay avoids it. Ground
rules that come from it:
- Set chat status from ACP's typed events, never by reading terminal output.
- New chats default to Ask, and Tay applies permission modes itself so they mean the same for
  every agent.
- Agents driving Tay through `tay mcp` can't start agents or change permissions unless allowed.
- Keep the app light: track idle memory and startup time.
- One consistent, Vim-like keymap, kept in `docs/KEYMAP.md`.
- No telemetry.

Out of scope for now: a mobile app, an embedded browser, and GitHub or Linear integrations.
